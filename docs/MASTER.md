## 3. 전체 구조
```
매일 02:10 KST  GitHub Actions (daily-pipeline) — 실거래가 채널 01:00 실행과 겹치지 않게
  run       : 테스트 → 뉴스 RSS 수집(Google 뉴스 연예 9·종합 4·국내 4·트렌드 4·꿀팁 4건) → Claude가 이슈 선정(위험 이슈 제외)
              → 이슈마다 Claude가 WebSearch/WebFetch로 원문 2~4개 확인 후 글+숏츠 대본 작성
              → 규칙 검사(qa.py) → Claude 독립 검수(원문 대조, 명예훼손·사생활 위험) → 반려 시 1회 재작성
              → 인물 사진·영상 검색(media.py, Commons)·Claude 사진 검수 → 숏츠 렌더(cards.py) → YouTube 업로드 → 사이트 빌드 → DB 커밋
  deploy    : GitHub Pages 배포 (public/, media/*.mp4)
  instagram : 배포된 mp4 URL로 릴스 게시
  report    : 오류가 있으면 실패 표시 → GitHub 이메일 알림
```
- 하루 발행 상한: 글 3편, 숏츠 3편 (11-18 사용자 결정으로 숏츠 2→3, 성과를 보고 조정)

## 6. 운영 방법
- 수동 실행: 새 저장소 Actions → daily-pipeline → Run workflow
- 긴급 중단: 저장소 변수 `PIPELINE_ENABLED=false` 또는 `config.toml`의 `[safety] enabled=false`
- 글 내리기: `python -m pipeline.run withdraw <slug>` → 커밋·푸시 → 다음 배포에서 빠짐 (YouTube·Instagram 게시물은 각 플랫폼에서 비공개 처리)
- 로컬 시험: `python -m pipeline.run all --fake-writer --tts silent` (Claude·뉴스 없이, data/demo.db)
- 로컬 테스트: `python -m unittest discover -s tests`

## 새 숏츠 방식 (11-21 정기 실행 적용)
- `pipeline/motion.py`: HyperFrames(무료, Apache 2.0)로 HTML+GSAP 장면을 크롬에서 녹화해 mp4. 음성과 단어 단위로 맞춘 자막(edge-tts 단어 시각), 장면 전환 번쩍임, 제목 띠 강조어 튀기기, 진행 막대.
- `pipeline/visuals.py`: 장면별 그림 — 인물 사진(기존 Commons) / 자료 사진(Commons 주제 검색 → Openverse, CC0·PD·BY·BY-SA, 화면에 "자료 사진"·출처) / Fluent 3D 이모지(MIT) / 큰 숫자 카운트업(값 길이에 맞춰 글자 크기 자동 조절) / 체크리스트.
- Claude가 장면 계획(`plan_visuals`, 대본에 있는 사실만)과 자료 사진 검수(`vet_topic_photos`: 일반인 얼굴·외국 장면·무관한 장면 제외)를 한다. 사진이 없으면 3D 이모지로 대신한다.
- 시범: `motion-pilot` 워크플로(수동, 업로드 없음). 렌더 시간 약 2~3분/편(59초 영상).
- 렌더 서버 준비: ffmpeg, fonts-nanum, fonts-noto-color-emoji, Node 22.
- 정기 실행: `config.toml [shorts] renderer = "motion"`. 새 방식이 실패하면 같은 음성으로 기존 카드 방식(`cards`)으로 다시 만든다. 길이 상한 60초(11-21, 58→60).
- 영상 설명의 사진 출처는 새 방식에서 `visuals.credits()`(자료 사진은 실제 사건 사진이 아님을 명시).

## 성과 학습 고리 (11-25 추가)
- 매일 새벽 실행의 첫 단계 `learn`: `pipeline/metrics.py`가 YouTube 숏츠 성과를 날짜별로 쌓는다(Data API 조회·좋아요·댓글 + Analytics 평균 시청 비율·공유, 안 되면 공개 페이지 조회수).
- `pipeline/learn.py`: 게시 2일 이상 지난 숏츠를 점수(조회수 × 시청 비율 가산)/채널 중앙값으로 상대 평가 → `data/playbook.json`.
  - 테마·화면 구성(motion=새 방식, frame=기존 카드) 가중치: 값별 중앙값을 표본 수만큼만 반영(수축), 0.5~2.0, 표본 3개 미만은 1.0으로 계속 시험. 실거래가 채널의 평균+상한 2.5 방식이 상한에 몰린 문제를 피함.
  - `config.toml [shorts] renderer = "ab"`: 영상마다 새 방식/기존 방식을 slug로 배정, 비율은 layout 가중치.
    11-26 사용자 결정으로 실험 중단, `renderer = "motion"`(전부 새 방식). layout 가중치는 계산만 하고 쓰지 않는다.
  - 분야별 성과는 글 선정 지침으로(다양성 유지 조건과 함께), 교훈(주 1회, 채점 8편 이상, Claude가 상·하위 비교, 최대 5개)은 선정·작성 지침으로 들어간다. 사실·출처·명예훼손·사생활 규칙이 항상 우선.
  - 교훈은 화면 구성·테마와 게시일 차이로 설명되는 것을 쓰지 않는다(가중치가 따로 다룸).
- 매일 04:00 예약 작업 "이슈 한입 매일 점검·현황판 갱신"이 실행 결과·학습 결과·오늘 글/숏츠 품질을 점검하고, 원칙에 어긋나는 교훈을 지우고, 반복 실수는 지침·규칙으로 고친다.
- 수동 실행: Actions → daily-pipeline → command=learn (학습만, 배포 없음).
